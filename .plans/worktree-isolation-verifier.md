# Отказы в worktree-сессиях: источник и решение (2026-10-28)

Повод: ретро polyglot `RETRO-2026-10-28`, cand-1. 68 из 72 повторных ошибок инструментов — отказы в
Bash у агентов, работающих в worktree. Задача: решить, нужна ли правка ядра, и как доставить правила
агентам, которых запускают вручную как `general-purpose`.

## Источник отказов (проверено)

Четыре формы из пяти отклоняет **сам Claude Code**, а не хук GSD. Текст отказа («This session/agent is
isolated in the worktree …», «too complex to verify that it stays inside the worktree», «redirects git
to the shared checkout via -C», «Blocked: sleep N followed by:») зашит в бинарник Claude Code
(`~/.local/share/claude/versions/2.1.312`). В версиях 2.1.310 (от 2026-10-24) и 2.1.311 он есть, более
старых версий на диске нет. В `~/.claude/hooks`, в хуках mn и в форке этого текста нет. Это не
«compound-cd prompt» из комментария `hooks/gsd-secret-read-guard.js:15`: тот срабатывает от правил
`Read()` deny и выдаёт запрос подтверждения, а не отказ.

Пятую форму (`/bin/ls -a | grep -i "^\.env"`) отклоняет **хук форка** `gsd-secret-read-guard`. Это его
ложное срабатывание: шаблон grep разбирается как имя файла, а обратный слэш считается разделителем
Windows-пути, поэтому `^\.env` превращается в `.env`. Исправление лежит в ветке
`fix/secret-guard-grep-pattern`.

Проверка на практике: три пробных агента с `isolation: "worktree"` в этом репозитории, по одному
Bash-вызову на команду.

| Форма | Итог |
|---|---|
| `cd <общий checkout> && …`, `git -C <общий checkout> …` | отказ |
| `X=$(git rev-parse --show-toplevel); …` — git внутри `$(…)` | отказ |
| `cd "$PWD" && git status` | отказ |
| `S=…; sed -n 1,2p $S/README.md` — переменная в аргументе sed | отказ |
| `node "$HOME/…/gsd-tools.cjs" …` — переменная в аргументе node | отказ |
| `node -e "…execFileSync('git',…)"` | отказ |
| **блок `worktree_branch_check` ядра** (`worktree-branch-check.md`) | **отказ** |
| **sentinel 0a и проверка абсолютного пути 0b** (`worktree-path-safety.md`) | **отказ** |
| **стандартный загрузчик `gsd_run`** (`gsd-run-resolver.md`) | **отказ** |
| `git rev-parse --show-toplevel`, `git status && git log -1` | проходит |
| `git rev-parse … > /dev/null && echo OK` | проходит |
| heredoc `cat > f <<'EOF'` в своём worktree | проходит |
| `sed -n 1,3p README.md` с литеральным путём | проходит |
| `cd /Users/govorin/forks && ls` — каталог вне обоих деревьев | проходит |
| `bash /литеральный/путь/скрипт.sh` (внутри скрипта `$(git …)` и `git -C`) | проходит |
| `node /литеральный/путь/gsd-tools.cjs query state-snapshot` | проходит |
| `sleep 2; cat README.md` | проходит (блок `sleep` срабатывает на файл вывода фоновой задачи) |

Правило проверки по пробам: git, sed и node должны стоять в простой форме, которую видно без
исполнения. Нельзя переменных и подстановок в их аргументах, нельзя `cd` перед git, нельзя `-C`
в общий checkout. Содержимое скрипта, запущенного по литеральному пути, Claude Code не проверяет.

## Пункт 1. Правка ядра

**Таблица «отказано → проходит» в промпт `gsd-executor` — нет.** Правила принадлежат версии
Claude Code: появились в 2.1.310, без документации и могут поменяться в любом релизе. К остальным
одиннадцати рантаймам GSD они не относятся. Им место там, куда их уже положили: личный скилл
`worktree-hook-rules` и `agent_skills` проекта.

**Но правка ядра нужна по другой причине.** Отказ получают собственные shell-блоки ядра, которые
исполнитель в режиме `harness-worktree` обязан выполнить: проверка ветки, sentinel, проверка
абсолютного пути, загрузчик `gsd_run`. На Claude Code ≥ 2.1.310 исполнитель GSD в изолированном
worktree не может выполнить эти блоки в той форме, в какой они записаны. Агент начинает
импровизировать: повторяет вызов в другой форме или пропускает проверку. Это дефект ядра, и он
касается всех пользователей GSD на Claude Code, а не только mn. В upstream об этом нет ни issue,
ни коммита (поиск по тексту отказа 2026-10-28).

Как правильно исправить (предложение, не реализовано):

1. Переложить проверки 0a, 0b, 0c, 0p и `worktree_branch_check` в глаголы `gsd-tools`
   (например, `worktree guard --stage branch|sentinel|abs-path|automated|pin … --json`) с
   типизированными кодами отказа. git тогда вызывается из node, и Claude Code его не проверяет.
   Заодно проверки становятся тестируемыми на типизированном выводе, а не на тексте bash.
2. Сделать так, чтобы установщик записывал для рантайма Claude литеральный абсолютный путь к
   `gsd-tools.cjs` (`node /abs/…/gsd-tools.cjs …`) вместо загрузчика с `$(git …)` и `$HOME`.
   Только эта форма запуска проходит проверку.
3. Добавить тест на эмитированные агенты Claude: в shell-блоках, которые исполнитель обязан
   выполнить в worktree, нет git или node с вычисляемыми аргументами.

Объём большой: загрузчик стоит в десятках агентов и workflow, двигает эмитированные байты всех
рантаймов, а у `plan-phase.md` осталось 8 байт до предела. Это архитектурное решение (ADR и
отдельный план), и делать его вслепую в рамках этой задачи нельзя. Нужно решение владельца.

## Пункт 2. Агенты `general-purpose`, до которых не доходит `agent_skills`

`agent_skills` встраивается только в промпты gsd-агентов (`src/init.cts`, блок `<agent_skills>`).
Варианты:

| Вариант | Достаёт general-purpose | Цена |
|---|---|---|
| **Хук `SubagentStart` в `~/.claude/settings.json` с `additionalContext`** | да, любого агента до первого вызова | один скрипт; так уже работает `cbm-subagent-reminder` |
| Строка в CLAUDE.md | да, но теряется в 50 КБ | прошлое ретро её предлагало, она не прижилась |
| Хук PreToolUse на `Agent`/`Task` с `updatedInput` (дописать преамбулу в prompt) | да | вмешивается в каждый бриф, сложнее отлаживать |
| Шаблон брифа оркестратора | только если оркестратор им пользуется | ручная дисциплина, ровно то, что не сработало |

**Рекомендация — хук `SubagentStart`** на пользовательском уровне, не в ядре. Он выдаёт короткую
таблицу и указание «загрузи скилл `worktree-hook-rules`», но только когда субагент работает в
worktree: его `cwd` лежит в `.claude/worktrees/` или `git rev-parse --git-dir` указывает на
`.git/worktrees/…`. В остальных случаях молчит. Правило приходит до первого Bash, а именно этого
требовало ретро («ссылка на записку не заменит вставку»). Перед реализацией надо проверить, какие
поля (`cwd`, `agent_type`) Claude Code передаёт во вход `SubagentStart`, и проверить хук пробным
агентом с `isolation: "worktree"`.

## Поправки к скиллу `worktree-hook-rules` (по пробам)

- `sed -n a,bp` с литеральным путём проходит. Отказ даёт `sed` с переменной в аргументах; `sed -i`
  лучше по-прежнему заменять на Edit.
- heredoc в своём worktree проходит. Отказ даёт связка с `cd` в другой каталог («too complex»).
- Добавить главное: **`gsd_run` и `node "$HOME/…/gsd-tools.cjs"` отклоняются. Вызывать
  `node /Users/govorin/.claude/gsd-core/bin/gsd-tools.cjs …` по литеральному пути.**
- Добавить: git внутри `$(…)` отклоняется. Вызывать `git rev-parse …` отдельным простым вызовом
  или переносить логику в скрипт, запускаемый по литеральному пути.
- Строку про `.env` после слияния `fix/secret-guard-grep-pattern` убрать: `grep "^\.env"` по выводу
  `ls` перестанет блокироваться. Чтение самих `.env*` по-прежнему запрещено.
