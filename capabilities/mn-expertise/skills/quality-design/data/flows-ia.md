# User Flow / IA / диаграммы

Минимум здорового файла: 1 Site Map + ключевые User Flow + State Diagram на каждый data-экран. Все диаграммы — в зоне `04 Flows`, физически отделённой от экранов в `03 Features` (дерево — `frame-hierarchy.md`).

## Четыре артефакта (у каждого своя цель)
- **Site Map / IA** — дерево разделов, структура и навигация (что где лежит). Сверху-вниз.
- **User Flow** — пошаговый путь задачи A→B с ветвлениями и действиями. Слева-направо.
- **State Diagram** — переходы между состояниями ОДНОГО экрана (idle→loading→content / →error→retry; empty→content).
- **Journey Map** — этапы + цели + боли + эмоции (продуктовая проработка).
User Flow обычно делают до Site Map (структуру строят вокруг путей).

## Ключевой принцип: узлы = ref на реальные экраны
Узел флоу — это `ref`/инстанс реального экрана (или его уменьшенный снимок), НЕ копия. Тогда при правке экрана флоу не устаревает — перенос single-source на диаграммы. Копия в флоу = вторая правда, которая разойдётся.

## Нотация
- Прямоугольник = экран/шаг; ромб = точка решения (ветвление, из него ≥2 ребра); овал = старт/финиш; стрелка = направление перехода.
- Стрелка реализуется как `path` (НЕ «connection» — такого типа обычно нет в схеме, провалит batch). viewBox 1:1 с размером ноды, иначе наконечник плывёт. У path нет детей — подпись это отдельный text над серединой, оба в group.
- **Подпись-триггер обязательна** на каждом нелинейном переходе («tap Buy», «submit form»). У развилки — ≥2 подписанных ребра.

Форма стрелки с подписью (пример; сверь со схемой инструмента) — path + text в group, viewBox 1:1 с width ноды:
```
group:
  path { geometry:"M0 9 L<len-12> 9 M<len-12> 3 L<len> 9 L<len-12> 15",  // линия + наконечник
         viewBox:[0,0,<len>,18], width:<len>, height:18, stroke:"$accent", fill:none }
  text { content:"<подпись-триггер, напр. «клик Далее»>", ... }  // над серединой
```
- **Swimlanes по ролям** (роли проекта + «Система»; типично: аноним/гость, авторизованный пользователь, привилегированная роль): смена дорожки = смена роли, наглядно показывает «нужна авторизация». Добавляет технический слой, которого нет у journey map.

## Обязательные флоу (типовой маркетплейс/продукт)
Типовые: онбординг/авторизация · основной путь «поиск → результат → деталь → целевое действие» · создание/публикация контента (wizard) · ключевое действие домена. Подбирай под конкретный продукт.

## Валидация флоу
Пройди сам; затем дай незнакомому человеку «думать вслух» — лови места заминок. Проверь: все ref ведут на существующие экраны, стрелки не висят, нет копий-дублей экранов.
