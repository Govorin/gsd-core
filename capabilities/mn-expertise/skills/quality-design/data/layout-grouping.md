# Группировка экранов и гигиена холста

Механика уровня `03 Features` и гигиена холста в целом. Дерево файла целиком (какие зоны есть и что в них) — `frame-hierarchy.md`.

## Feature-first (платформа ВНУТРИ фичи)
Индустриальный стандарт для единой команды (Airbnb/Spotify/Atlassian): всё про «Главную» в одном месте, платформы сравниваются рядом, дрейф между платформами виден.
```
Zone-секция (продуктовый поток) → Feature-фрейм → группа Web {под-колонки 1440/834/390}
                                                 → группа Mobile {iOS/Android}
                                                 строки = состояния (канон из visual-language.md)
```
- Web-разрешения — под-колонки ВНУТРИ группы Web, не наравне с mobile.
- Guest vs Authorized — variant компонента шапки, не отдельная колонка/строка экрана.
- Email и технически-иные контуры (своя разметка) — отдельной зоной.

## Модель фрейм-зоны (экраны — ДЕТИ зоны, не россыпь)
Зона = контейнер, физически держащий экраны, а не баннер-надпись рядом:
```
Zone/<Name>  frame, layout:vertical, gap, padding, fill:surface-muted, cornerRadius
├── Zone Title    text
├── Screens Row   frame, layout:horizontal, alignItems:start  ← экраны как дети (Move сюда)
└── [note] <Name> frame, dashed-бордер, не-белый фон          ← заготовка комментариев
```
Экраны кладутся в Screens Row через Move — layout сам строит ряд, координаты не нужны. Аннотации (`[note]`/`[spec]`/`[motion]`/`[a11y]`/`[data]`) ставятся на любом уровне рядом с описываемым узлом — типы и правила в `frame-hierarchy.md` → «Аннотации».

## Гигиена холста
- **Плоский корень:** только зоны/экраны/компоненты/крупные контейнеры. Голый text/icon/shape, оказавшийся в корне, — Move внутрь зоны, к которой он относится (подпись → в её заголовок, заметка → в `[note]`-блок); ничей — в Archive. Исключение: flow-стрелки живут в корне внутри group.
- **Бэнды сверху-вниз** по фичам/типам, единый ритм отступов. Что кладётся вправо, а что вниз, и в каком порядке — `frame-hierarchy.md` → «Семантика осей». **Ноль перекрытий** — перекрытие = потерянные узлы и непредсказуемый z-order.
- Cover/Index-зона с навигацией-якорями (на холсте 100k+ px навигация без неё дорогая). Статусы `stable/beta/deprecated/coming-soon`. **Archive-зона** для устаревшего вместо удаления — сохраняет историю.
- Удаляй артефакты-описания старого слоя (баннеры-надписи, висячие метки, бриф-заметки). Но предпочитай **фрейм-контейнер-зону** баннеру-надписи: контейнер держит экраны и двигается с ними.

## Координаты раскладки (как считать)
Раскладку считай программно из реальных размеров (сними snapshot top-level). Алгоритм бэндов: каждый бэнд на своём Y, внутри слева-направо с гаттером; следующий бэнд = `y += maxHeightТекущегоБэнда + VGAP`. VGAP подбирается под масштаб холста и высоту самых высоких блоков (не зашитая константа — на больших макетах это тысячи px). Проверь результат: посчитай попарные пересечения прямоугольников top-level — должно быть 0. Перемещай single-threaded, по бэнду за пачку (потолок пачки — `canvas-gotchas.md` → «batch и операции»).

**Лучше координат — layout-контейнер.** Если инструмент поддерживает, оберни все зоны в один родительский `layout:vertical` контейнер с gap: тогда зоны выстраиваются автоматически и НЕ МОГУТ наезжать (layout управляет), а корень остаётся плоским (контейнер + Kit). Это устойчивее ручных Y-координат — добавление зоны не требует пересчёта.

## Layout-механика (flex-подобная, но с ограничениями)
Обычно: `layout` horizontal/vertical/none, gap, padding, justifyContent, alignItems(start/center/end). Обычно НЕТ: wrap, baseline/stretch, %/vh/calc/margin. Сетки карточек — вручную ряды (нет wrap), карточки фикс. ширины. Ряд = horizontal + gap + alignItems:start. Заголовок зоны держи отдельным уровнем или absolute — ребёнком layout-контейнера он сдвинет всё содержимое. Vложенность: `fit_content` течёт вверх, `fill_container` вниз только при фикс. родителе; все уровни fit_content + фиксировать листья — безопасно.
