# Грабли canvas-инструментов (Pencil-класс) — READ FIRST перед правками

Эти ловушки выстраданы практикой; каждая стоит часов отладки или тихой регрессии. Под конкретный инструмент проверяй спайком, но паттерны типичны.

## Запись может быть in-memory (НЕ на диске)
MCP/API-запись часто идёт в in-memory документ редактора и **не флашится на диск синхронно** (и не по короткому таймеру). Последствия:
- **Verify на лету — через инструмент** (read-tool инструмента: get_state/batch_get/snapshot), НЕ через файл на диске. Файл/git показывают СТАРОЕ состояние до сохранения.
- **Read-only анализ файла** (если формат — обычный JSON) с диска валиден только для baseline ДО сессии и финала ПОСЛЕ сохранения; на лету не доверять.
- **Коммит в git — только после явного сохранения файла** (часто это делает владелец вручную в редакторе; команды «сохранить» из API может не быть). Попроси сохранить, дождись, проверь `git status` → `M`, потом коммить.
- **Откат:** git ненадёжен пока не сохранено → откат через обратную операцию в инструменте. Спайк в начале: правка → чтение с диска → видно ли изменение → как форсируется флаш.

## id и ссылки
- **Move/reparent СОХРАНЯЕТ id** → инстансы (`ref` по id) не ломаются. Перемещай источники только через Move.
- **Copy+delete МЕНЯЕТ id** → ломает все refs на узел. Существующий узел переносится только Move; Copy оставь для создания нового.
- **Update обычно НЕ меняет id/type/ref.** Смена `ref` у инстанса = пересоздание (Delete+Copy), а не Update. Перед этим проверь, что на id инстанса нет внешних ссылок (флоу!).
- Нельзя Update потомка сразу после Copy в одном batch — Copy пересоздаёт детей с новыми id; кастомизация копии — через descendants внутри самого Copy.
- id reusable-компонента задаёт система — нельзя назначить свой; после создания читай реальный id.

## Дефолтные значения не пишутся в файл
Движок нормализует: дефолтные `layout:horizontal`, `alignItems:start` и т.п. применяются, но НЕ сохраняются в узел. Их **отсутствие в чтении ≠ баг** — фрейм «без layout» уже ведёт себя как horizontal+start. Увидел «пустое» свойство — оставь как есть и потрать batch на реальный дефект; классическая ошибка — массово «чинить» ряды, которые и так выровнены.

## Sizing-циркулярность и схлоп
- **fit_content-родитель + fill_container-ребёнок по одной оси = схлоп в 0.** Хотя бы один ребёнок должен быть фикс./fit_content. Полноэкранным макетам в layout-ряду задавай ФИКС. height.
- Пустой fit_content-фрейм без детей схлопывается (warning Collapsed) — норм временно при создании зоны до наполнения, исчезает после Move детей внутрь.
- Текст: требует явного режима роста (auto/fixed-width/fixed-width-height) и обязательной заливки (иначе невидим); width/height без режима роста игнорируются.

## batch и операции
- batch обычно атомарен: ошибка → откат всего batch; warnings чинить следующим batch. Держи ≤25 операций/batch (если лимит инструмента ниже — он и есть потолок).
- batch_get/read падает целиком, если хоть один запрошенный id отсутствует — запрашивай id, свежесть которых подтверждена текущим чтением.
- Удаление контейнера обычно рекурсивно уносит детей — проверь, что внутри нет нужных источников, и что Delete рекурсивен.

## Свой audit-скрипт (окупается)
Если файл — обычный JSON, заведи read-only CLI (парсер) с проверками-gate, гоняй после каждой секции (на диске — для baseline/финала):
`orphan-refs` (ref на несуществующий id) · `source-в-нелегальном-месте` (`reusable` вне трёх разрешённых мест — `02 UI Kit`, `[kit] <Feature>`, screen-source; полный список — `frame-hierarchy.md` → «Инварианты дерева». Старое имя проверки `source-вне-Kit` вводит в заблуждение: два из трёх легальных мест — не общий Kit) · `hardcoded-hex` (цвет-ключи с literal hex кроме ч/б/прозрачного) · `deprecated-namespace` (легаси-токены) · `spacing-вне-шкалы` · `simulated-delete` (что осиротеет при удалении набора — «external refs INTO set: 0» = безопасно). Summary-only вывод, чтобы не забивать контекст.
