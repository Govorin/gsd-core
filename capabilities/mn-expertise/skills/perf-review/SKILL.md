# Perf review — линза, а не общий совет

Ревьюер GSD объявляет производительность вне рамок дословно: «Performance issues
(O(n²) algorithms, memory leaks, inefficient queries) are NOT in scope for v1».
Этот скилл закрывает ровно названный пробел и ничего сверх него.

**Правило применения:** линза включается, когда диффа касается запроса к БД,
обработчика маршрута или клиентского хука данных. Для чистой функции без I/O
она молчит — производительность там не измеряется чтением, и догадка о ней
дороже пользы.

## Почему это ревью, а не профилирование

Профилировщик отвечает «что медленно **сейчас**». Ревью отвечает «что станет
медленным **на данных**». Разница практическая: запрос без `LIMIT` на таблице
из 200 строк неотличим от правильного, пока строк не станет 200 000, и к тому
моменту он уже в проде и вызывается из трёх мест.

Поэтому здесь ищутся не замеры, а **формы**, которые деградируют с ростом.

## 1. N+1 — запрос внутри цикла по результату запроса

Самый частый и самый дорогой класс.

```ts
// ✗ один запрос за списком + по одному за каждой связью
const books = await db.select().from(booksTable);
for (const b of books) {
  b.author = await db.select().from(authors).where(eq(authors.id, b.authorId));
}
```

**Что искать в диффе:** любой `await db.` внутри `for`, `map`, `forEach`,
`Promise.all(list.map(...))` по результату предыдущего запроса.

**Как чинится:** `with` (relational query), `inArray` одним запросом, или `join`.

```ts
const books = await db.query.books.findMany({ with: { author: true } });
```

**Почему тесты это не ловят:** тест с двумя записями делает три запроса вместо
одного — и проходит. Форма отказа линейна по данным, а фикстуры не растут.

## 2. Фильтр без индекса

```ts
await db.select().from(events).where(eq(events.tenantId, id));
```

**Что искать:** колонка в `where` / `orderBy`, которой нет в `index()` схемы.
Проверяется чтением файла схемы рядом, не догадкой.

**Особый случай — составной индекс:** индекс `(a, b)` не помогает фильтру по
одному `b`. Порядок колонок в индексе — часть контракта, и он читается слева
направо.

## 3. Невыгруженная связь и `select *`

`db.select().from(t)` тянет все колонки. На таблице с `jsonb` или `text` это
мегабайты на строку там, где нужны три поля.

**Что искать:** `select()` без аргумента там, где потребитель читает 2–3 поля.
**Как чинится:** `select({ id: t.id, title: t.title })`.

## 4. Запрос без `LIMIT` на растущей таблице

**Что искать:** `findMany` / `select` без `limit` по таблице, которая растёт со
временем (события, логи, сообщения, аудит). Списки справочников — не растут,
и там это нормально.

**Формулировка находки:** не «добавьте LIMIT», а «эта таблица растёт линейно
по времени; запрос без границы вернёт всё, что накопилось с запуска».

## 5. Ключ кэша без инвалидации

Redis и React Query — одна и та же ошибка в двух местах.

```ts
// ✗ пишем под ключ, который никто не удаляет при изменении
await redis.set(`book:${id}`, JSON.stringify(book));
```

**Что искать:** запись в кэш, для ключа которой нет ни `del`, ни TTL, ни
`invalidateQueries`. Кэш без инвалидации — не кэш, а способ показать
пользователю вчерашние данные.

Для React Query: мутация без `onSuccess`-инвалидации соответствующего
`queryKey`.

## 6. Клиентская выборка внутри `useEffect` без зависимостей

```ts
// ✗ перезапрос на каждый ререндер
useEffect(() => { fetchBooks().then(setBooks); });
```

**Что искать:** `useEffect` с фетчем и пустым/отсутствующим массивом
зависимостей, либо с зависимостью-объектом, пересоздаваемым каждый рендер.

**Замечание по стеку:** в проекте с React Query такой код обычно означает, что
хук не завели вовсе — находка не «почините эффект», а «это должен быть
`useQuery`».

## Как формулировать находку

**Называй форму и порог, а не ощущение.** «Медленно» — не находка. «Запрос в
цикле по результату предыдущего: на 1000 книгах это 1001 обращение к БД» —
находка: её можно проверить и оценить.

**Указывай, где именно.** Файл и строка, как в любом ревью.

**Не предлагай кэш как первое средство.** Кэш поверх N+1 прячет проблему и
добавляет инвалидацию, которую тоже придётся сопровождать. Сначала запрос,
потом кэш.

**Молчи, когда нечего сказать.** Диффа без I/O не даёт материала для этой
линзы, и находка ради полноты обучает читателя пролистывать её вывод —
ровно так линза перестаёт работать.
