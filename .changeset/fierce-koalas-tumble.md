**Tool preflight: a plan whose executor lacks a tool it names halts instead of running under another agent** — a plan declares the tools its executor needs beyond its own in `requires_tools:` (a `.pen` file in `files_modified` implies `mcp__pencil__*`). `verify plan-structure` now carries `tool_preflight` (and a warning) when the installed executor's `tools:` does not grant one; the plan checker reports it as a warning with the fix. Tools only named in task prose are a warning, never a halt. `/gsd-execute-phase` halts at execute:pre on it for the plans the run will execute (`check mn-tool-preflight`, honouring `--wave` and `--gaps-only`; `workflow.tool_preflight`, default on) and `/gsd-quick` checks its plan before the executor spawn (`verify tool-preflight`). The message names the missing grants and the fix — `gsd-tools config-set agent_tools.<agent> '[…]'`, then re-installing GSD the way it was installed — read from the agent file Claude Code loads (the project's `.claude/agents/` ahead of the global one); an absent or unreadable agent file, or a runtime whose installer translates grants (Copilot, Kilo, …), is reported as unknown, never as a pass.
